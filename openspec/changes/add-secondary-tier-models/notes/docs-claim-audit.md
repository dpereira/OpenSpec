# `docs/commands.md` policy and activation claim audit

This audit supersedes the earlier in-dispatch/three-attempts-per-slot claim map and the interim "6.x pending" map. It covers every policy and activation statement in the `/opsx:models` section, including the `openspec models` CLI wording. Sources are grouped by implementation layer: 2.x configuration (`src/core/agent-models.ts`), 3.x persistence/state (`src/core/model-routing-policy.ts`), 4.x CLI (`src/commands/models.ts` and `src/cli/commands/models.ts`), and 6.x generated routing (`src/core/templates/opencode-tiers.ts` and `src/core/opencode-tier-assets.ts`). All layers are now implemented and covered by the focused suites (`test/core/agent-models.test.ts`, `test/core/model-routing-policy.test.ts`, `test/commands/models.test.ts`, `test/core/opencode-tier-assets.test.ts`).

No claim in the page equates configured policy or installed assets with live enforcement. The cooldown, persistence, and recovery descriptions match the implemented policy/state semantics and the generated router's admission behavior; activation is reported as advisory or unverified until a running host attests enforcement.
