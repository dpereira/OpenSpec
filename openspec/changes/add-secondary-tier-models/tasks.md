Integration constraints for 4.1 and 6.3: on-disk asset status proves installation readiness only; report restart-required or activation-unverified unless a running adapter attests loaded enforcement. Emit routing code into the existing self-contained generated router through the build/template pipeline, without imports of this repository's `src/` or a global OpenSpec installation. Routing is cross-dispatch only: no in-dispatch model switching and no resubmission of failed work.

## 3. Dispatch-level routing policy (parallel with 2.x)

- [x] 3.1 Rework the host-free decision core in `src/core/model-routing-policy.ts` to dispatch-level persistence (injected clock, no host APIs, no timers of its own): keep the normalized availability categories (authentication, credits/quota, unavailable model, transport, rate limit, overload, server) versus never-qualifying outcomes (task/tool errors, refusal, quality, invalid request, context limits, cancellation, unknown); replace the in-dispatch attempt/slot machine with observation accumulation — each host retry observation and each dispatch terminal failure is one evidence item for its pairing, a success clears the streak, and the pairing is marked for fallback only when evidence is persistent in one category (consistent observations within a retried dispatch, or two consecutive un-retried failed dispatches); category changes and non-qualifying failures never mark a pairing; expose the fallback decision to the session state layer without any in-dispatch retry loop. Verify: `pnpm exec vitest run test/core/model-routing-policy.test.ts` green using fake clocks only — retried-dispatch consistency marks fallback after one dispatch, single un-retried failure does not mark, two consecutive un-retried same-category failures do mark, category change and non-qualifying failures never mark, and a success clears accumulated evidence.

Verify: `pnpm exec vitest run test/core/model-routing-policy.test.ts` green with fake-clock cases for cooldown 300s (dispatch during cooldown starts on secondary; post-expiry dispatch probes), probe concurrency (exactly one leased probe, others on secondary), probe success / qualifying failure / nonqualifying failure outcomes, restart clearing state with no replay, and config-identity isolation plus safe resume semantics per the cases above.
